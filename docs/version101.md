# 版101：?perf=1 にカクつきの原因を分ける数を足す（2026-10-21）

ユーザーの依頼（02:34「コード全体の徹底的なパフォーマンス改善」）。4回に分けた（ユーザー決定：①戦いの毎コマのスクリプト処理 → ②描画の回数 → ③1コマだけ長い引っかかり → ④入力の遅れ）。
カクつくのは「戦い」・端末は iPhone（Safari）と Android（Chrome）。実機の `?perf=1` の数は、あとで送ってもらう。
その数で原因を分けられるように、①の前に、表示を足した。

## ?perf=1 の表示（1秒ごと）
```
FPS 41  さいだい 88 ms  おそい 7
びょうが 130 かい  3D 456x987  low
しょり 4.2 ms  びょうがCPU 6.1 ms
がぞう 49 MB
```
| 表示 | 意味 |
|---|---|
| おそい（新） | その1秒で、1コマが 25 ms（60コマ/秒の1.5コマ分）より長かった回数＝カクつきの回数 |
| しょり（新） | 1コマの、スクリプト・動きの計算などの CPU の時間（平均。Godot の TIME_PROCESS） |
| びょうがCPU（新） | 1コマの、絵を描く命令を作って送る CPU の時間（平均。描く前の準備＋画面を描く命令） |

- 「しょり＋びょうがCPU」が 16 ms に近い → CPU が重い（①・②が効く）。
- 1コマの時間（1000÷FPS）が、その合計よりずっと長い → GPU（絵をぬる部品）が重い見こみ（画面の画素・シェーダーを軽くする）。
- うしろの体力の表示と重なっても読めるように、うすい黒の下じきを付けた。

## ファイル
