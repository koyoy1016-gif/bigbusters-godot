# 版96：重さの調査と計測（2026-10-20）

ユーザーの依頼（21:23「ロビーキャラのモーション変更とコード全体の調査・軽量化」）の 2 つめ。ここでは**測っただけ**で、ゲームは変えていない。

## 測る道具（tools/。測るだけで、見た目・動きは変えない）
| 道具 | 測るもの |
|---|---|
| `perf_flow.gd` | 画面の流れごと（ロビー → 戦い → ロビー を3回）：1コマの時間・すべての _process の時間（前後をはさむ印で）・描画の回数・三角形・メモリ・戦いの _process の仕事ごとの時間・HUD を描く時間 |
| `perf_parts.gd` | 部品を1つずつ消して、1コマの時間・描画の回数・三角形がどれだけ減るか（描く重さの目安）。`quick` で全部ありの数だけ |
| `perf_memory.gd` | ロビー → 戦い → ロビー を何回かして、メモリと、残っている資源（ファイル） |
| `perf_hitch.gd` | 戦いを2回して、1コマだけ長い「引っかかり」（1回目だけ＝はじめての準備） |
| `perf_battle_fixed.gd` | 決まった3つの場所・夕方と夜で、描画の回数・三角形・1コマの時間（直す前と後を同じ条件で比べる） |

注意：この作業用の環境には GPU がない。「描画あり」は llvmpipe（CPU で絵を描く）なので、時間は**部品どうしを比べる**ためだけに使う。描画の回数・三角形の数・スクリプトの時間は、スマホでも同じ傾向。

## 見つけた原因（優先度）
| # | 原因 | 根拠 | 直し方 | 優先度 |
|---|---|---|---|---|
| 1 | 道路・地形・建物が、それぞれ1つの大きな形 | 道路の三角形の 44% はカメラの後ろ、49% は 330 m より遠い。画質「低」の「330 m より遠い建物を出さない」設定（visibility_range）は、形が1つなので、まん中からの距離で決まり、いつも全部出ていた（効いていなかった） | 形を前・遠い前・後ろに分ける（版97） | A |
| 2 | 街灯の光の輪 | 夕方はほぼ見えない（強さ 0.04）のに、透明な重ね描き | 夜になった時だけ出す（版98） | A |
| 3 | はじめての戦い・はじめての覚醒の引っかかり | 戦いに入る 1回目 1.5 s／2回目 0.75 s。はじめての覚醒＋酒瓶落としで 1コマ 0.92 s（2回目はなし）。画面なしでは引っかからない → 描く準備（シェーダー作り） | 戦いを読みこむ時に、使う材質を先に描いておく | B |
| 4 | 戦いのあと、メモリが増えたまま | 画面なし +20 MB（4回くり返しても同じ＝もれではない）。描画あり static +134 MB・画像 +53 MB | 何が残っているかを、もっと調べる | B |
| 5 | ロビーのキャラの描画が多い | 4人で三角形 6.5万・描画 66回（1人 約15回＝材質の数） | 材質をまとめる（形の作り直しが必要・危ない） | C |
| 6 | さかいの透明な壁・霧・空 | llvmpipe では重いが、スマホの GPU では軽い種類／見た目の役目がある | 変えない | C |
