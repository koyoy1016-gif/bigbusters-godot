## 3. 要る区画（メッシュ）

PLATEAU のファイルは、日本を四角に分けた「**メッシュ**」ごとに分かれている。
- 建物・道路・都市設備・木：**3次メッシュ**（約1km四方。8けたの番号）
- 地形：**2次メッシュ**（約10km四方。6けたの番号）

スクランブル交差点（北緯 35.6595・東経 139.7006 あたり）から計算すると、**交差点は 53393596 の区画の、左下の角の近く**にある（西のはしまで約50m、南のはしまで約130m）。そのため、まわり400mをふくむには **4つ**の区画がいる。

```
         西 ←                → 東
     ┌──────────┬──────────┐
  北 │ 53393595 │ 53393596 │   ★＝スクランブル交差点
     │          │★         │      （53393596 の左下の角の近く）
     ├──────────┼──────────┤
  南 │ 53393585 │ 53393586 │
     └──────────┴──────────┘
     地形（2次メッシュ）：533935
```

**未確認**：番号は、交差点の緯度・経度から計算したもの。ZIP の中の図郭図（`..._indexmap_op.pdf`）で、交差点がこの区画に入っているか見てほしい。

## 4. データの取り方（あなたにお願いすること）

こちらの作業場所からは、国のサイト（G空間情報センター）に入れない（試したら、つながらなかった）。そのため、**ダウンロードと、必要なファイルの取り出し**をお願いしたい。

### 手順
1. **ページを開く**
   パソコンのブラウザで、次のページを開く（スマホより、パソコンがおすすめ。ファイルが大きいため）。
   https://www.geospatial.jp/ckan/dataset/plateau-13113-shibuya-ku-2025
   （ページの名前：「3D都市モデル（Project PLATEAU）渋谷区（2025年度）」）
2. **使い方の決まりを読む**
   ページの「使用許諾」「ライセンス」のところを、一度読んでおく。
3. **CityGML の ZIP をダウンロードする**
   ページの「データとリソース」の中の、**CityGML** と書いてあるもの（「v5」などの印が付いていることがある）を選んで、ダウンロードする。
   - 3D Tiles・MVT・GeoJSON は、**いらない**。
   - 大きいので、時間がかかる。空き容量は、ZIP の3倍くらいあると安心。
4. **ZIP をひらく（展開する）**
   - Windows：ZIP を右クリック →「すべて展開」。**できるだけ短い場所**（例：`C:\plateau`）に展開する（フォルダの名前が長すぎると、Windows でうまく展開できないことがある）。うまくいかない時は「7-Zip」などの展開ソフトを使う。
   - Mac：ダブルクリック。
5. **図郭図を見る**
   展開したフォルダのいちばん上にある、名前が `..._indexmap_op.pdf` のファイルを開き、渋谷駅の西どなりのあたりに `53393596` の区画があるか見る。
6. **必要なファイルだけを、新しいフォルダに集める**
   新しいフォルダ（名前は `shibuya_plateau`）を作り、展開したフォルダの中の **`udx`** フォルダから、次のファイルをコピーする。
   ファイルの名前は「**区画の番号_種類_6697_op.gml**」の形（例：`53393596_bldg_6697_op.gml`）。名前の最後が少しちがう時（`_2_op` など）は、**番号で始まるものを全部**。

   | フォルダ（種類） | 何か | コピーするファイル | 大事さ |
   |---|---|---|---|
   | `udx/bldg` | 建物 | 名前が **53393585**・**53393586**・**53393595**・**53393596** で始まる `.gml` | **必須** |
   | `udx/tran` | 道路 | 同じ4つの番号で始まる `.gml` | **必須** |
   | `udx/dem` | 地形（高さ） | 名前が **533935** で始まる `.gml` | **必須** |
   | `udx/frn` | 都市設備（信号・街灯など） | 同じ4つの番号で始まる `.gml` | あるとよい |
   | `udx/veg` | 木 | 同じ4つの番号で始まる `.gml` | あるとよい |
   | `udx/brid` | 橋（歩道橋など） | 同じ4つの番号で始まる `.gml`（あれば） | あるとよい |

   - **`_appearance` で終わるフォルダ（写真の模様）は、コピーしない**。大きいうえに、看板や広告の写真がうつっていることがあり、ゲームでは使わないため。
   - 上の表にない種類（`luse`・`urf`・`fld`・`lsld` など）は、いらない。
7. **ZIP にまとめて、このチャットに添付する**
   `shibuya_plateau` フォルダを ZIP にする（Windows：右クリック →「圧縮（zip形式）」／Mac：右クリック →「圧縮」）。この形式のファイルは、ZIP にすると、かなり小さくなる。
   - 大きすぎて添付できない時は、**建物（bldg）→ 道路（tran）→ 地形（dem）→ のこり** の順に、分けて送る。
   - **未確認**：このチャットに添付できる大きさの上限。

### うまくいかない時
- ダウンロードのボタンが見つからない：ページの「データとリソース」の一覧の中で、名前に「CityGML」とある行を開くと、ダウンロードのボタン（または URL）がある（**ボタンの名前・置き場所は未確認**）。
- 番号のファイルがない：その区画には、その種類のデータがない、ということ。あるものだけでよい。
- 区画の番号が合わない（交差点が図郭図の別の所にある）：図郭図の番号を教えてほしい。こちらで直す。

### 5-2. 手順
1. **バックアップ**：作業の前のコミットに目印を付ける（`git tag before-shibuya-map`）。いつでも、今のマップにもどせる。
2. **変換の道具を作る**（`tools/plateau_to_glb.py`。Python）
   - CityGML（XML）を読む。大きいファイルでも、少しずつ読む（メモリを使いすぎない）。
   - **座標を直す**：PLATEAU は「緯度・経度・高さ」（EPSG:6697）。**交差点のまん中を (0, 0, 0)** にして、**1 = 1m**、東 → +X、上 → +Y、南 → +Z にする（Godot と今のゲームの単位）。400m くらいの範囲なら、この計算の誤差は数cm。
   - **交差点のまん中**：最初は北緯 35.6595・東経 139.7006 で始め、道路のデータ（tran）から、交差点の車道の形のまん中を計算して決めなおす。
   - **高さ**：地形（dem）から、交差点のまん中の地面の高さを 0 にする。まわりの道路・建物は、本物の高さのまま（坂がそのまま出る）。
   - **切る**：交差点から半径 350〜400m より外は消す。
   - **建物**：LOD2（屋根あり）があれば LOD2、なければ LOD1。壁・屋根・底を分けて、**色だけ**付ける（写真の模様は使わない）。色は、建物の高さ・用途でかえ、夕方の街に合う色にする。窓の明かりは、ロビーと同じように、計算（シェーダー）で描く（画像を使わず軽い）。
   - **道路**：LOD3 があれば、車道・歩道を分けて色を付ける（車道は暗い灰色、歩道は明るい灰色）。
   - **信号・街灯・木**：都市設備（frn）・植生（veg）の LOD3 があれば、形をそのまま使う。なければ、木は簡単な形を、本物の位置に置く。
   - **まとめる**：建物を、近い・遠いの数個のまとまりにして、描く回数を減らす。
   - 書き出す：`assets/maps/shibuya/shibuya.glb`（Godot がそのまま読める 3D の形式）。数（三角形・建物の数・ファイルの大きさ）を表示し、上から見た図（PNG）も作って、位置が合っているか確かめる。
   - 元の CityGML は、**リポジトリに入れない**（大きいので）。変換の道具と、できた .glb だけを入れる。
3. **交差点を描く**
   - 戦いの場所（±15m）は、**平らなアスファルトの面**を、地面より少しだけ上に置く（キャラが地面に埋まらない・浮かない）。
   - **スクランブル交差点の白いしま（横断歩道）**は、本物の道路の形に合わせて、ゲームで描く（道路の LOD3 に横断歩道があるかは**未確認**。あれば、それを使う）。
4. **取り込み**：Godot は .glb をそのまま読める（プラグインはいらない）。当たり判定は作らない（このゲームは、床の高さと ±15m の正方形で判定しているため）。
5. **古いマップと入れかえる**
   - `_build_world()` の**緑の板（Ground）を作るのをやめ**、`scripts/stage/map_loader.gd`（新規）で渋谷を読む。**古い板は残さない**（重なって表示されない）。
   - マップの設定は `data/maps.json`（新規）：使う .glb、交差点のまん中の緯度・経度、向き、高さの合わせ、空・霧・光の色、見える距離。
6. **今の仕組みとつなぐ**
   - 自分・ボス・味方・小さい敵の出る所、動ける範囲（±15m）、カメラ、光の向きを、交差点に合わせる。
   - 小さい敵の輪（半径9m）が、交差点の車道からはみ出さないか確かめる。
   - カメラは、ボスと街の両方が見えるよう、少し上を向ける・少し引く（数値で調整。縦と横の画面の両方）。
   - ハイライトの再生（上から見た図）にも、交差点の形をうすく出す（あとで・任意）。
7. **軽くする**（ブラウザ・スマホのため）
   - 半径 350〜400m で切る。遠くの建物は LOD1（箱）にして、近くだけ LOD2。
   - Godot の「見える距離（visibility range）」で、遠い物を描かない。画質「低」では、早めに消す。霧で、遠くの切れ目を見えなくする。
   - 小さすぎる物（物置・細かい部品）は消す。
   - 目安：.glb は 5〜8MB 以下、三角形は全部で 20〜30万以下（**仮の目標。iPhone で測って見直す**）。今の書き出し（約58MB）とあわせて、合計100MB未満を守る。
8. **テスト**（`tests/test_map_shibuya.gd` 新規＋今の全テスト）
   - 古い緑の板がない。渋谷のマップが1つだけ出ている。
   - 戦いの場所（±15m）の中に、建物がない。戦いの場所の床は平ら（高さ 0）。
   - キャラの足が床の高さに合う（埋まらない・浮かない）。
   - 交差点のまん中のまわりの決まった建物が、決まった方向・距離にある（位置の確かめ）。
   - 三角形の数・ファイルの大きさが目安の中。出典が書いてある。
   - 写真：戦いのカメラ（縦・横）、上から見た図。
9. **iPhone で確かめてもらう**（重さ・見え方）。

## 6. 気をつけること
- **看板・広告・お店のロゴは出さない**：写真の模様（`_appearance`）は使わない。大きな画面（街頭ビジョン）は、形だけ置き、ゲームの中の自作の絵（例：BIG BUSTERS のロゴ）を映すことはできる。
- **銅像など、作品にあたる物は作らない**（例：ハチ公の像）。
- 建物の形は本物どおりだが、建物の名前・お店の名前は、ゲームの中に出さない。
- 出典は必ず書く（2章）。
- これは法律の判断ではない（私は弁護士ではない）。気になる所は、公開の前に確かめる。

## 7. データが足りない時の代わり
- **屋根の形（LOD2）がない建物**：LOD1（箱・高さは本物）で作る。ゲームの絵柄（色の面）に合うので、見た目はそれほど悪くならない。
- **道路・横断歩道の形が足りない**：OpenStreetMap（だれでも編集できる世界の地図。ライセンスは ODbL で、ゲームの中に「© OpenStreetMap contributors」と書くのが条件）の道路の形を使う、または、地図を見ながらこちらで描く（写真や看板は使わない）。
- **ファイルが大きすぎて送れない**：パソコンで「PLATEAU GIS Converter」（国の無料の変換ソフト。Windows・Mac）を使い、上の区画のファイルを glTF（.glb）にしてから送る。設定の細かい所（座標の選び方）は、その時に一緒に見る（**未確認**）。
  https://www.mlit.go.jp/plateau/learning/tpc30/
