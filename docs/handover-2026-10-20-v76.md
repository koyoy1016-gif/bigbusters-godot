## 2. 版69〜76で決まったこと・変えたこと（古い順）

### 版69：ボスの怒り（いまも有効）
- **ボスの怒り**：ボスの体から3m以内で味方の攻撃が当たった回数を、直前の5秒で数える。
  - 20回以上ある間は怒る。回数が下がれば、すぐ元にもどる。
  - 怒っている間は、つかみ投げの重みが2倍になる。
  - 怒っている間に始まる攻撃は、1.25倍の速さになる（攻撃の長さを1.25で割り、攻撃の中の秒 u を1.25倍で進める）。
  - 必殺技は速くしない。
- 部品は `scripts/combat/boss_rage.gd`、数値は `data/boss_attacks.json` の `ai.rage`。
- **通信中は怒らない**（`online: false`）。画面ごとに数がちがい、ボスの攻撃がずれるため。ユーザーが了承済み。
- 版69では、つかみを「1秒の間に『にげる』7回で逃げる」にした。**これは版70で、逃げる仕組みごと消した。**

### 版70：投げ・剣士の体力・剣士の一覧
- **つかまれたら必ず投げられる**。
  - 「にげる」の連打、みんなのダメージで外れる仕組み（free_damage）、AIの連打、「にげる」ボタンの表示を、全部消した。
  - つかまれている間、ボタンは「×」で効かない。
  - 外れるのは、つかまれた人が倒れたときと、戦いが終わったときだけ。
  - つかむ時間は1秒。剣士をすぐ投げるつかみ（版68。0.25秒、1戦1回）は残っている。
- **投げられた人がほかの人にぶつかる仕組み（版67）を消した**。テスト `test_throw_collide.gd` も消した。
- **剣士（指示書の「忍者風の剣士」＝剣士）の体力は190**。`characters.json` の hero_swordsman と、`prototype_stick.json` の roles.p1 の2か所にある。
- 剣士の攻撃の一覧を `docs/swordsman.md` に作った。テスト test_v70 が、一覧の数字とデータが合うかを見る。

### 版71：AIの味方の判断（`scripts/combat/ai_ally.gd` の `_think`、数値は `data/ai_allies.json` の `tactics`）
- 先読み：`stick_prototype.gd` の `boss_forecast` が、ボスのいまの攻撃を2秒先まで、0.2秒きざみで調べる（0.25秒ごとに作り直す）。
  - `Attacks.hazards(攻撃, 秒)` は、同じ入力なら同じ結果を返すので、先の秒を入れて調べられる。
  - つかみの位置は、先読みでは決めない（`_attack_ctx(a, u, peek=true)`）。
- 自分の場所に当たる物があるとき：
  - Yの跳んでいる間（0.16〜0.78秒）に全部当たり、どれもジャンプでよけられるなら、**Y（かわし斬り）でよける**。
  - 走って間に合うなら**走る**。両方できるときは半々。
  - Yにはまだ早いなら、ちょうどよい時刻まで待つ。
- 当たる物がないとき：「すき」（次の攻撃まで＋0.45秒、最大2秒）の中で終わる攻撃だけを使う。すきが長いと五段斬り。
- 体力が35%未満のときと、当たった直後の1.5秒は用心する。すきが1.2秒未満なら、届かない所で待つ。
- 読みそこねは15%（skill 0.85）。
- 巨大酒瓶ライドは計算が重いので、先読みしない（`forecast_skip`）。
- 比べた結果（4戦）：
  - AIが受けたダメージ：93.6 → 59.5（1人1分あたり）
  - AIが倒れた回数：4.8 → 2.2（1戦あたり）
  - AIが与えたダメージ：−17%
  - 勝つまでの時間：約158 → 約172秒

**整理のやり方（決まり）**
- **状態の変数は、まとめ役（stick_prototype.gd）に残す**。テスト56本が `s.grab_state` などを直接見ているため。
- 関数だけを部品へ移す。部品は `extends RefCounted` で、`var b: StickPrototype` を持ち、本体の変数・関数は `b.` を付けて使う。
- 本体には `class_name StickPrototype` を付けた（版76）。
- 部品の中だけで使う変数は、部品へ移す。
- 本体の外（本体の残り・テスト・道具・ほかのスクリプト）から呼ばれる関数は、本体に同じ名前の「取り次ぎ」を残す（`## → battle_xxx.gd` と書いてある）。
- 本体の const（preload）は、部品にも写す。

**道具（`tools/refactor/`）**

| 道具 | 使い方 |
|---|---|
| `split_tool.py` | `python3 tools/refactor/split_tool.py scripts/prototype/stick_prototype.gd scripts/prototype/battle_xxx.gd 部品の変数名 部品のクラス名 "説明" 関数名,関数名,...` で、関数を移し、`b.` を付け、取り次ぎを残す |
| `wire.py` | `python3 tools/refactor/wire.py 部品のクラス名 battle_xxx.gd 部品の変数名 "説明"` で、本体に preload と `var 部品 := 部品.new(self)` を足す（リポジトリの一番上で実行） |
| `alltests.sh` | 全テストを CI と同じ確かめ方で回す |

**道具の注意（つまずいた所）**
- 元のコードに **`b` という名前のローカル変数**（瓶・箱）があると、本体の `b` とぶつかる。道具は `bk` に名前を変える（直し済み）。
- 本体（Node3D）の関数（`add_child`・`is_inside_tree` など）にも `b.` を付ける。道具の中に一覧がある。一覧にない物が出たら、足す。
- **関数の引数の初期値**（例：`pool: Array = hazard_nodes`）は、道具では直せない。手で直す（整理1では `pool_in: Variant = null` にした）。
- 本体の頭に `class_name` を2回書かないこと（整理1で一度起きた）。
- `static func` が本体の変数を使っていたら、道具は止まる。
