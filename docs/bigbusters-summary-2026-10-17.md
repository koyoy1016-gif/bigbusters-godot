## 1. 決まった設計（決定）

### 1-1. 2アプリ構成

| | アプリ1（友達用） | アプリ2（収益化用） |
|---|---|---|
| 目的 | 友達20〜30人と遊ぶ | ストアで公開し、買い切りで収益化を目指す |
| 遊び方 | 合言葉の部屋で最大4人（足りない分はAI） | 1人＋AIの仲間3人 |
| 通信・フレンド | あり（Firebase） | なし |
| セーブ | あり（アカウント方式） | あり（端末内保存を推奨） |
| 公開先 | GitHub Pages（無料） | Android先行、iPhoneは後 |
| 目標時期 | MUST機能は来週（10/24ごろ） | 数週間〜数か月 |

- 戦闘などの土台は共通にし、通信の部分だけアプリ1に付ける
- Firebaseのプロジェクトは、新しく作る（既存のゲームとは混ぜない）

### 1-2. 共通の土台

- コンセプト：**4人で1体の大型妖怪を倒す**（変えない部分）
- キャラクター：4体。名前と見た目は、仮のものから始める
- 大型妖怪：1体から始める。攻撃パターンは2〜3種類
- ダメージ計算（仮）：攻撃力 × 技の倍率 ÷（防御 + 基準値）
  - 計算は1つの関数にまとめ、数値はデータファイル（JSON）に分ける
- 操作（スマホ）：横画面固定。左に仮想ジョイスティック、右に通常攻撃・スキル・必殺
- キャラ、技名、台詞、音、絵は、すべて自作（他社の作品と似せない）

### 1-3. アプリ1の機能

| 優先度 | 機能 |
|---|---|
| MUST（来週） | 合言葉（4桁）で部屋に入る、AIで足りない人数を補う、接続状態の表示、自動で再接続 |
| SHOULD（来週以降） | アカウント登録、フレンドコード（8文字）での追加、オンライン表示、招待 |
| LATER（数週間〜） | ステージを4〜5つに増やす、キャラの3Dモデル、解放条件、ホストの交代 |

### 1-4. ログイン

- ゲームがIDを自動で割り当てる（通し番号）。本人がパスワード（6文字以上）を決める
- Googleログインと匿名ログインは使わない
- パスワードを忘れた場合：新しいIDで登録し直す
- 内部では Firebase Authentication の「メール/パスワード」を使い、IDを `p{ID}@（任意のドメイン）` の形に変えて登録する

### 1-5. 通信の仕組み

| 用途 | サービス |
|---|---|
| アカウント・フレンド | Firestore |
| 対戦中の同期・オンライン表示 | Realtime Database |

- ホスト（部屋を作った人）がゲームの状態を管理し、ほかの人に送る
- 更新は1秒に約10回（仮。テストで調整）
- 切れたとき：画面に「再接続中」と表示し、自動で同じ部屋に戻る。戻れなければAIが担当する
- 途中参加は不可
- Photon（Godot用アドオン）は、ブラウザ版で動かない可能性が高いので使わない

### 1-6. 画面

1. タイトル（部屋を作る、部屋に入る、ログイン、新規登録）
2. ホーム（フレンド一覧、フレンドコード）
3. 部屋の待機画面（合言葉、参加者、開始ボタン）
4. 戦闘画面（HP、接続状態、操作ボタン）
5. 結果画面

### 1-7. アプリ2の収益化の形

- **無料体験版（1ステージ）＋全ステージ解放を買い切り**（決定）
- 購入の記録は、端末内のセーブに残す
- ガチャは入れない

## 2. 通信の設定（次にやること）

詳しい手順は、先に渡した `firebase-setup-guide.md` にあります。ここでは流れだけをまとめます。

### 2-1. あなたがやること（Firebase）

1. https://console.firebase.google.com/ を開き、**新しいプロジェクト**を作る（例：`bigbusters-new`）。Googleアナリティクスは無効にする
2. **Sparkプラン（無料）のまま**にする。Blazeには変更しない
3. Authentication で「メール/パスワード」だけオンにする（メールリンクと、Google・匿名はオフ）
4. Firestore を **本番環境モード**で作る。場所は東京（`asia-northeast1`）
5. Realtime Database を **ロックモード**で作る。場所はアジアのうち日本に近いもの
6. ウェブアプリを登録する（Firebase Hostingのチェックは外す）。表示された設定値をメモする
7. 私に教えること：プロジェクト名、作った場所、エラーがあればその文字（`apiKey` は貼らなくてよい）

※ テストモードは使わない（30日後に誰でも読み書きできる状態になる）。
※ ルール（誰が何をできるか）は、実装のときに書いてテストしてから設定する。

### 2-2. 通信の試作（10/19〜20）

1. PowerShellで、プロジェクトのフォルダに移動して `claude`（Claude Code）を起動する
   ```
   cd "C:\Users\吉野 光陽\.copilot\repos\bigbusters-godot"
   claude
   ```
2. 最初に、仕様書を読むようにClaude Codeへ伝える。`CLAUDE.md`（作業のルール）も作る
3. 2台のスマホで、同じ合言葉の部屋に入る
4. 片方で動かした箱が、もう片方でも動くか確かめる
5. 機内モードや電波の切り替えで、自動で戻るか確かめる
6. iPhoneとAndroidの両方で試す

### 2-3. 先にやるべき実験（iPhone）

iPhoneのブラウザでは、Godotの書き出しが落ちる報告があります。作り込む前に、**簡単な3DのシーンをiPhoneのSafariで動かす**実験をします。

## 3. どんなゲームにしたいか（構想。設計書には入れていない）

### 3-1. 舞台
- 北千住・上野・東京・品川の**駅周辺を、小さな範囲で再現**した街で戦う
- 北千住でボスを倒したあと、電車に乗って上野へ向かう演出（既存のゲームと同じ流れ）
- 既存のゲームよりも、街と全体の質を上げたい

### 3-2. 街の作り方（提案）
- 写真のようなリアルさではなく、**ミニチュア風**にする
- 素材：国土交通省のPLATEAU（無料。商用利用ができ、クレジット表記が必要）で建物の形を取る
- 道路、線路、駅、ランドマークは自作する。小物は無料素材（Kenney、Quaternius、Poly Haven）で埋める
- 最初は**北千住の1エリアだけ**を作り、作業の流れと重さの限界を確かめる
- 実在の店の看板、ロゴ、鉄道会社のロゴ、駅のメロディなどは、そのまま使わない

### 3-3. キャラの作り方（提案）
- Blenderで自作し、費用は0円に収める
- 人型の4体は、同じ骨格・体型にして、色とパーツで違いを出す
- テクスチャは貼らず、単色にして、輪郭線で見栄えを出す
- 動きはMixamo（無料、Adobe ID必要）を使う。動きは6種類程度に絞る
- 大型妖怪は人型でなければ、パーツごとに動かす
- Quaternius（CC0）の素材を土台にして、大きく作り変えてもよい（ライセンスは各パックで確認）

## 6. 注意・リスク

- **iPhoneのブラウザ**：落ちる報告がある。合計100MB未満、メモリ150MB前後を目標にし、実機で確かめる
- **ブラウザの重さ**：画像（テクスチャ）が一番重い。1024×1024の画像は約5.3MB（ミップマップ込み）で、50枚なら約267MB。単色か小さい画像にする
- **他社の作品との類似**：キャラ、技名、台詞、音、絵は自作にする。タイトルも紛らわしくないものにする（今の「BIGバスターズ」は見直す）。公開前に専門家へ相談する
- **ガチャ**：入れない
- **税金**：会社員で、副業などの所得が年間20万円を超える場合は、所得税の確定申告が必要。住民税は別。自分の場合は税務署か税理士に確認する
- **Androidの公開条件**：個人アカウント（2023年11月13日以降に作成）は、12人以上のテスターが14日間続けて参加する非公開テストが必要。登録は18歳以上
