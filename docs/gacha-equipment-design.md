# ガチャ・装備の設計書（案）

作成：2026-10-19（Claudeの案。あなたが判断する場所は「決めること」に集めた）

## 守る決まり（CLAUDE.md のルール6。ユーザー決定 2026-10-18）
- ガチャは、**遊んで貯めた無料コインだけ**で回す。お金では回せない。お金で回すガチャは作らない。
- **各景品の当たる確率を、回す前に画面に表示する。**
- 複数の景品を揃えると別の景品が出る仕組み（コンプガチャ）は作らない。
- 法的な確認は、していない（**未確認**）。無料コインだけでも、公開前に、専門家か公式の資料で確認する。

## 全体の流れ
1. 戦って、コインをもらう（いま：勝ち50、負け10。`data/game_flow.json` の `reward_win_coins` / `reward_lose_coins`）
2. ロビーの「ガチャ」でコインを使って、装備を引く
3. ロビーの「そうび」で、キャラに装備をつける
4. 装備をつけると、見た目（剣・ベルトなどの小物）と、少しだけ性能が変わる

## 装備
- 枠は3つ：**武器・からだ・アクセサリー**（まず3つ。増やすのは後で）
- 効果は小さく：全部つけても、**合計で +20% まで**（初心者と、装備を集めた人の差が、大きくなりすぎないように）
- 効果の種類（案）：攻撃力 +%、HP +%、足の速さ +%、技の待ち時間 −%
- 見た目：`data/attachments.json` の小物（骨につける板・円柱などの形）と同じ仕組みを使う。装備 `id` と小物 `id` を結ぶ
- 種類：武器5、からだ5、アクセサリー5 ＝ **15個からはじめる**（足りなくなったら増やす）

### 装備のデータ（案。`data/equipment.json`）
```json
{
  "sword_basic":   {"slot": "weapon",    "name": "ふつうの けん", "rarity": "N",  "bonus": {"attack_power": 0.00}, "attachment": "sword_basic"},
  "sword_red":     {"slot": "weapon",    "name": "あかい けん",   "rarity": "R",  "bonus": {"attack_power": 0.05}, "attachment": "sword_red"},
  "belt_basic":    {"slot": "body",      "name": "ふつうの ベルト", "rarity": "N",  "bonus": {"hp": 0.00},           "attachment": "belt_basic"}
}
```
（数字は仮。決めるのは `docs/balance-sheet.md` を見ながら）

## ガチャ
- 1回の値段：**100コイン**（案）。10回まとめは、1000コイン（おまけなし。お得にしない＝お金の感覚を持ち込まない）
- レア度と確率（案。**全部、画面に出す**）

| レア度 | 確率 | 出るもの |
|---|---|---|
| N | 60% | ふつうの装備（効果ほぼなし。見た目ちがい） |
| R | 30% | 効果 +3〜5% |
| SR | 9% | 効果 +6〜8%、見た目が目立つ |
| SSR | 1% | 効果 +9〜10%、特別な見た目 |

- 各景品の確率も表示する：同じレア度の中は等しい（例：SSRが3種類なら、1つあたり約0.33%）。表示は、小数点以下まで出す
- ダブったとき：「かけら」になる。かけらで、手持ちの装備を強くできる（上限あり。合計 +20% の中）
- **天井**（○回で必ず出る）：入れる案（例：100回でSSR1つ）。無料コインだけなので、問題は少ないが、表示は必須
- 確率の表示の画面を先に作り、**テストで「表示した確率の合計が100%になる」ことを確かめる**

### ガチャのデータ（案。`data/gacha.json`）
```json
{
  "cost": 100,
  "rarity_odds": {"N": 0.60, "R": 0.30, "SR": 0.09, "SSR": 0.01},
  "pity": {"pulls": 100, "guarantee": "SSR"},
  "pool": ["sword_basic", "sword_red", "belt_basic"]
}
```

## 保存
- 持ち物・つけている装備・かけら・天井のカウント：ログインずみなら、いまの記録（コイン・勝ち数・キャラ）と同じ場所（`saves/{sid}/data`）に入れる。**Firebaseのルールの変更が1回必要**
- 通信中の他のプレイヤーの装備の見た目：キャラの共有（`chars`）と同じやり方で、装備 `id` も共有する（ルール変更あり）
- 性能の効果は、**自分の端末で計算する**（他の人の性能は、見た目だけ共有）。サーバーのいらない作りなので、ズルを完全には防げない（フレンドと遊ぶ前提のゲームなので、許容）

## 作る順番（案）
1. `data/equipment.json`・`data/gacha.json`を作る
2. 確率の計算（ガチャの1回分）と、テスト（確率の合計、天井、かけら）
3. 「ガチャ」画面（確率の表を先に出す）
4. 「そうび」画面（3つの枠）
5. 装備の見た目（小物）と、性能の反映（ダメージ計算 `scripts/combat/damage.gd` は1つの関数のまま。倍率は、呼ぶ側で渡す）
6. 保存（ルール変更とまとめて）

## 決めること（あなたの判断）
1. 1回の値段（100コイン）と、勝ったときの報酬（50コイン）のバランス。1回ガチャを回すのに、2勝いる。それでいいか
2. 効果の上限（+20%）で、いいか
3. 天井を入れるか（入れる案）
4. 「かけら」で強くする仕組みを入れるか（最初は入れず、ダブりはコインに変える、でもよい）
5. 他社の作品の名前・絵・音は使わない（ルール5）。装備の名前・見た目は、自作にする
