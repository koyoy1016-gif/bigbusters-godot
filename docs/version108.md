# 版108：覚醒が重い（調べて直した）（2026-10-21）

ユーザー（09:42）：「まだアプリが重いから軽量化して。プレイ中、覚醒時がとにかくおもい。」
画質と通信の速さは下げない（02:47 の決まり）。

## 調べたこと（この機械：PC・画面なしと、CPU で描く llvmpipe）
同じ種・同じ時計で、ふだん（夕方）と覚醒（夜）を比べた（`tools/perf_awake.gd`）。

| | ふだん | 覚醒 |
|---|---|---|
| 1コマの CPU（画面なし・平均） | 1.0〜1.1 ms | 1.0〜1.2 ms |
| 描画の回数（high・平均） | 216 | 189 |
| 描く三角形（high） | 約 61万 | 約 60万 |

- **ずっと続く重さは、ふだんと覚醒でほぼ同じ**だった。夜は、シェーダーの数を変えるだけ（同じシェーダー）。空の光の計算（反射・まわりの光）は使っていないので、夜に変わる間も作り直さない（Godot のソースで確認）。
- ちがいが出たのは、**覚醒の時に「はじめて」起きること**と、**覚醒の攻撃の計算**だった（下の 1〜3）。

## 直したこと
### 1. 覚醒の曲の「はじめて鳴らす」で止まる（ブラウザだけ）
- ブラウザの書き出しでは、音は決まりで「サンプル」（はじめて鳴らす瞬間に、**音の全部を読みほどいて**ブラウザに渡す）。
  覚醒の曲（34.7 秒）は、その1コマで全部を読みほどく：**PC で 55 ms**（スマホではその数倍の見こみ・未計測）。読みほどいた音は **1曲 13〜15 MB** メモリに残る（曲5つで 45 MB）。
  → 曲（`scripts/audio/bgm.gd`）は「ストリーム」（流しながら少しずつ読みほどく。1コマ PC 0.03 ms 弱）にした。止まらず、メモリも曲のファイルの大きさだけ。
  → ストリームはメインの処理の合間に音を作るので、コマが長い時に音がとぎれないよう、音のためておく時間（`project.godot` の `audio/driver/output_latency.web`）を 50 → 100 ms にした（曲が鳴り始めるのが少し遅れるだけ。効果音は関係ない）。
- 効果音（39こ・合計 30 秒）は短いので、サンプルのまま。はじめて鳴らす時に止まらないよう、画面を作る時（読みこみの間）に先に読みほどく（`sfx.gd` の `preload_samples`。ブラウザの時だけ）。
- 覚醒・勝ち・負けの曲のファイルを、覚醒の瞬間ではなく、戦いを作る時に読みこむ（`bgm.preload_tracks`）。
  → 覚醒の瞬間（倒れて起きる間）のいちばん長いコマ（PC・画面なし・2回）：**5.3〜5.5 ms → 3.5〜3.9 ms**。

### 2. 覚醒・ボスの攻撃で、はじめて出る見た目の「シェーダー作り」（ブラウザだけ）
- スマホのブラウザ（WebGL）は、はじめて使う描き方を描く瞬間にシェーダーを作るので、その1コマが止まる。
  戦いが始まってからはじめて出る描き方（`tools/perf_firstdraw.gd`）が **10 種類** あった：酒の大雨の雨・巨大酒瓶ライドの瓶としぶき・火祭りのライター・飛び散る粒・蘇生の輪・予告の面・弾や銃口の光（技の形）など。
- `scripts/fx/draw_warm.gd`（新規）：同じ形・同じ材質の「写し」を作る。戦いの画面ができた時（版106 の技の先出しといっしょに）、**カメラの前の地面の下（見えない所）に3コマだけ**出して、先にシェーダーを作らせる。
  - ボスの攻撃の見た目（`battle_attack_fx.gd` の `prewarm_sources`）：はじめて使う時に作っていた物（雨・巨大酒瓶・酒瓶・しずく・ライター・粒・火・ぬれた床・跳ぶ影・予告の面）を、いま作る（隠れたまま）。
  - 覚醒の見た目（`boss_model.gd` の `prewarm_sources`）：覚醒の小物（はちまき・一升瓶）・大きな手・酒のしぶき。
  - 倒れた時の蘇生の輪（`battle_revive.gd` の `prewarm_source`）。数字は地面を通して見える作りなので、すきとおる色で描く。
  - 弾・銃口の光・プレゼントなど、形が自分の色を持つ物（`battle_skills.gd` の `_collect_props`）。
  - 元の見た目は動かさない・見せない。写しは3コマで消す。
- 結果（llvmpipe・`tools/perf_firstdraw.gd`。ボスの攻撃19種類を1つずつ出し、最後に覚醒）：戦いが始まってからはじめて出る描き方 **10 種類 → 0 種類**。全部、戦いの画面ができたコマ（「はじめる」の前）に移った（そのコマではじめて描く種類 22 → 35）。
- 写しを出している3コマの画面：写しを出す／隠すで撮りくらべ（`tools/shot_prewarm.gd`）。ちがったのは、時間で動く大画面（写しと関係なし）と、地面の影のふち 5 画素（3コマの間だけ。影の計算の範囲が少し変わるため）だけ。

### 3. 覚醒の攻撃の、毎コマの計算のやり直し
- 巨大酒瓶ライド（覚醒の必殺技）は、道と投げる瓶の落ちる所（瓶ごとに 40 回ためす）を、1コマに何回も（自分・AI の味方3人・ボスの動き・見た目）毎コマ計算しなおしていた。酒の大雨の安全地帯（最大 400 回ためす）・チラシの向き・酒瓶の落ちる所も同じ。
- `boss_attacks.gd`：同じ入力なら同じ答えになるので、答えを覚えておく（キーは計算に使う値だけ。最大 64 こ）。答えは前と同じ（テストで、攻撃の全部の時刻の当たり場所が同じことを確かめた）。
- 結果（PC・スクリプトの時間・ほかに何も動かしていない時）：

| | 前 | 版108 |
|---|---|---|
| 巨大酒瓶ライドの間（1コマのスクリプト） | 1070 µs | **918 µs**（ride_throws 227 µs → 0） |
| 酒の大雨の間 | 1028 µs | **830 µs**（storm_safe 203 µs → 0） |
| ライドの当たり場所（攻撃の全部の時刻） | 97 ms | **37 ms**（2.6 倍） |

## ためして、やめたこと
- キャラの影を「輪郭線の殻の影」だけにする（体の影の形を出さない。影の三角形が約 17万へる）：キャラ同士・体の部分どうしの影がうすくなる所が出た（画素の 2.9% が変わる）。画質が変わるので、やめた。

## 残り（つぎの候補）
- 描く三角形が多い（high で 1コマ約 79万：キャラ1人 約 3.3万 × 色・輪郭線・影）。遠い時に細かさを自動で下げる（LOD）と、見た目をほぼ変えずに減らせる見こみ。
- 召喚の兵隊（はじめて出る時に、キャラの形を作る）も、はじめての引っかかりがある見こみ。
