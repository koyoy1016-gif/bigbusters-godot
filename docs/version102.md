# 版102：軽量化① 戦いの毎コマのスクリプト処理（2026-10-21）

ユーザーの依頼（02:34「コード全体の徹底的なパフォーマンス改善」）の①。見た目・動き・通信は変えない（02:47 ユーザー：画質と通信の速さは下げない。ほかの所で速くする）。

## 測り方（新しい道具・測るだけ）
- `tools/perf_profile.gd`：Godot のスクリプトのプロファイラー（`-d` で起動）で、**関数ごとの時間**（self＝その関数だけ・total＝中で呼んだ物も）と回数。
- `tools/perf_cpu.gd`：画面なし・`--fixed-fps 60` で、**1コマの CPU の時間**（スクリプト＋動きの再生などのエンジンの仕事。描く仕事はふくまない）。ゲームの中の時計も 1コマ＝1/60 秒で進める（ボスの攻撃の時間が、この機械の速さに左右されない）。30秒の戦い（AI の味方とボスが自由に戦う）。
- どちらも PC（このための作業機）の数。スマホのブラウザではもっと遅いが、**減った割合**は同じ傾向。

## 見つけた原因（関数ごと・30秒の戦いの1コマあたり）
| 原因 | 場所 | 根拠（直す前） |
|---|---|---|
| キャラのモデルのファイルがあるかを、毎コマ3回、ファイルを調べていた | `character_data.gd` の `has_model`（`battle_net.gd` の `_update_other_view` から） | 1回 37µs・1コマ **110µs**（スクリプト全体の 11%） |
| 体力の表示を、毎コマ全部描き直していた（変わっていなくても） | `battle_hp_hud.gd`（`_draw_party`・`_draw_boss`・`layout` を毎コマ2回・円の点を毎回計算） | 1コマ **約290µs**（スクリプト全体の 30%） |
| 設定の色（"#rrggbb" の文字）を、毎コマ読み直していた | `battle_hud.gd`（ボタン・スティック・文字・ダメージの数字） | 毎コマ 20 回以上 |
| キャラの定義を、毎回、全員の中から1人ずつさがしていた | `character_data.gd` の `find`（毎コマ9回） | 1コマ 28µs |
| 自分の性能の辞書を、呼ぶたびに写していた | `stick_prototype.gd` の `role()`（毎コマ2回以上） | 1コマ 19µs |
| 色が同じでも、毎コマ材質に書いていた | `stick_prototype.gd` の `_process`（自分の箱・印） | 書くたびに材質の送り直し |

## したこと
- `battle_hp_hud.gd`：体力の表示を **自分の板（overlay の子・overlay の絵より下＝前と同じ重なり）** に描き、毎コマは「見た目を決める数」（体力・たおれ・光る・ボスの割合と帯・覚醒・顔の絵の数・画面の大きさ・通信の仲間の体力）だけ集めて、**前のコマと同じなら描かない**。場所の計算は画面の大きさごとに1回。円の点は1回だけ作る。ボスの帯の動きは毎コマ進める（前と同じ速さ）。
- `character_data.gd`：`has_model` は答えを覚える（ファイルは遊んでいる間に変わらない）。`find` は id の索引を作る（同じ配列・同じ数なら作り直さない）。
- `stick_prototype.gd`：`role()` は同じキャラ・同じ枠の間は前に作った物を返す（呼ぶ所はどれも読むだけ）。材質の色は変わった時だけ書く。
- `battle_hud.gd`：設定の色を1回読んだら覚える。
- `perf_overlay.gd`・`game_flow.gd`：`?perf=1` の字を日本語の字が入った文字の形で出す（スマホで「さいだい」などが □ になっていた）。
