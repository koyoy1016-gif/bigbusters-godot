# コードの点検と整理の計画（2026-10-19・版51）

前のゲーム（tobatoban）のように「1つのファイルに何でも入って、直すたびに別の所が壊れる」形にしないための点検。

## よくできている所（このまま続ける）
- 数値は `data/*.json` にある（HP・攻撃・時間・色・大きさ）。
- ダメージの計算は `scripts/combat/damage.gd` の1か所だけ。
- 小さく分かれた部品がある：攻撃の時間の進み（`player_actions.gd`）、当たりの範囲（`hit_area.gd`）、ボスの攻撃の予定（`boss_attacks.gd`）、画面の流れの決まり（`flow_logic.gd`）、部品のまとめ（`mesh_merge.gd`）、形の道具（`shape_kit.gd`）。
- テストが37本（Godot）＋59件（ブラウザ側のJS）あり、全部合格してからしか公開しない。

## 整理の計画（動きは変えずに、1段ずつ。毎段テスト全部合格→コミット）
1. **戦いの本体を分ける**（いちばん効果が大きい）
   - `scenes/battle/battle.gd`（まとめ役。各部品を呼ぶだけ、300行以内）
   - `battle_input.gd`（スティック・ボタンのタッチ）／`battle_hud.gd`（文字・ボタン・体力バーの描画、縦横の配置）／`battle_camera.gd`
   - `battle_net.gd`（部屋の状態を読む・位置を送る）
   - `boss_controller.gd`（ボスの攻撃の見た目・体の動き・つかみ）／`ai_team.gd`（AIの味方3人のまとめ）
   - `stick_prototype` という名前はやめる（`battle`）
2. **画面を1つずつ分ける**：`screens/title.gd`、`lobby.gd`、`formation.gd`、`account.gd`、`friends.gd`、`result.gd`。`game_flow.gd` は「どの画面を出すか」だけ
3. **ボスを「形」と「動き」に分ける**：`boss_rig.gd`（腕・手・しっぽ・姿・点滅。どのボスでも共通）＋ `bosses/oni_builder.gd`（鬼の形だけ）＋ `data/bosses/oni.json`。次のボスは builder と json を足すだけ
4. **共通の道具を1か所に**：ブラウザ呼び出し（`web_bridge.gd`）、設定の読み込み（`config.gd`）、色は読み込み時に1回だけ変換
5. **片づけ**：使っていない物を消すか `experiments/` に移す。起動シーンを本物の画面にする

## これからの決まり（汚くしないため。CLAUDE.md に足す案）
- 1つのファイルは 400行まで を目安。こえたら、仕事ごとに分ける。
- 1つのスクリプトは、1つの仕事。「〜と〜をする」と説明が2つになったら分ける。
- 新しいボス・ステージ・キャラは「データ＋小さな形のファイル」を足すだけで増やせるようにする（コードのコピーをしない）。
- 同じ処理を2か所に書かない。2回目が出たら、共通の道具にする。
- 部品ごとにテストを持つ。
