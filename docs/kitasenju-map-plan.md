## 3. 差し替えの設計（このプロジェクトに合わせた形）

### 3-1. 考え方
- 戦いの決まり（ボスの攻撃・AI・通信・ハイライト）は、**まんなか ±15m の平らな正方形**を前提に作ってある。これを全部作り直すと、ほぼ全部のテストと調整がやり直しになる。
- そこで、**北千住の本物の街の中に、平らで広い所（駅前の広場や大きな交差点）を選び、そこに ±15m の戦いの場所を置く**。まわりの建物・道路は本物の位置に置く。戦いの場所の外の建物は「見える壁」になる（中に入れない）。
- 戦いの場所の中に建物が入ってしまう所は選ばない。どうしても入る場合は、その建物だけ消す（データを見て決める）。
- 候補（**未確認・データを見て決める**）：北千住駅 西口の駅前（バスの乗り場のまわり）、東口の駅前、宿場町通りの交差点。

### 3-2. 変えるファイル・足すファイル
| すること | ファイル |
|---|---|
| 北千住の3D（建物・道路・地面をまとめた .glb） | `assets/maps/kitasenju/kitasenju.glb`（新規）。元の CityGML は**リポジトリに入れない**（大きいので） |
| CityGML → .glb の変換の道具 | `tools/plateau_to_glb.py`（新規。Python。こちらで作る） |

| 数値 | `data/prototype_stick.json`：`ground_size`・`ground_color` は使わなくなる。`bounds`・`boss_position`・カメラは、選んだ場所に合わせて見直す |

### 3-3. 座標と大きさ
- PLATEAU の CityGML は、**緯度・経度・高さ**（EPSG:6697＝日本の測地系 JGD2011）。
- 変換の道具で、**選んだ広場のまんなか（緯度・経度）を (0, 0, 0)** にして、**東 → +X、南 → +Z、上 → +Y、1 = 1m** にする（Godot は Y が上、1単位 = 1m。今のゲームも1m単位）。1km くらいの範囲なら、この簡単な計算で誤差は数cm。
- 高さ：広場の地面の高さ（地形 dem から読む）を 0 にする。今のゲームの床の高さ `ground_y` に合わせる。
- 向き：北を画面の奥にするか、駅の向きに合わせるかは、`data/maps.json` の回転で決める（カメラは今の向きのまま）。

### 3-4. 軽くする（ブラウザ・スマホのため）
- 範囲を**駅を中心に半径 300〜400m** に切る（それより遠くは見えないので消す）。
- 建物は**色だけ（頂点カラー）**、写真の模様（テクスチャ）は使わない（CLAUDE.md のルール8）。
- 建物を**1つの形にまとめる**（数百〜数千の建物を、近い・遠いの2〜3個のまとまりに。描く回数が減る）。
- 遠くの建物は LOD1（箱）、近くだけ LOD2（屋根あり）。Godot の「見える距離（visibility range）」で、遠い物を描かない。
- 小さすぎる建物（物置など）は消す。
- 目安：.glb は 5MB 以下、三角形は全部で 20万以下（**仮の目標。iPhone で測って見直す**）。
- 影：低画質では影なし（今と同じ）。

## 4. 具体的な手順

### 手順A：あなたにお願いすること（データを取ってくる）
1. ブラウザで「G空間情報センター」の **「3D都市モデル（Project PLATEAU）足立区（2025年度）」** のページを開く
   https://www.geospatial.jp/ckan/dataset/plateau-13121-adachi-ku-2025
2. ページの注意書き（利用規約・測量法のところ）を読む
3. **CityGML** の ZIP をダウンロードする（大きい。数百MB〜数GBの見こみ。**未確認**）
4. ZIP をひらき、中の **`udx`** フォルダを見る。その中に `bldg`（建物）・`tran`（道路）・`dem`（地形）のフォルダがある
5. 北千住駅のまわりの区画のファイルだけを取り出す。区画の番号（3次メッシュ：日本を約1kmの四角に分けた番号）は、こちらで計算して **`53394694`**（駅のある区画）と **`53395604`**（その北どなり）。
   - `bldg` の中：名前が `53394694_bldg_...gml` と `53395604_bldg_...gml` のファイル
   - `tran` の中：名前が `53394694_tran_...gml` と `53395604_tran_...gml` のファイル
   - `dem` の中：名前に `533946` か `533956` をふくむファイル（地形は区画の分け方がちがうことがある。**未確認**）
   - 同じ名前で始まるフォルダ（`..._appearance` など、写真の模様）は**いらない**
   - **未確認**：番号は、駅の位置（北緯35.749・東経139.805）から計算した。ZIPに入っている「図郭図」のPDFで、駅がこの区画に入っているか見てほしい
6. 取り出したファイルを、このチャットに添付する（大きすぎて添付できない時は、ZIP にまとめるか、建物だけ先に）

### 手順B：こちらでやること（データが届いてから・版89〜）
1. **バックアップ**：作業の前のコミットに目印（タグ）を付ける（`git tag before-kitasenju-map`）。今のマップに戻したい時は、いつでもこの時点にもどせる
2. **変換の道具を作る**（`tools/plateau_to_glb.py`）：CityGML を読んで、緯度経度 → メートルに直し、範囲で切り、色を付け、まとめて、`assets/maps/kitasenju/kitasenju.glb` を書く。数（三角形・建物の数・ファイルの大きさ）を表示する
3. **場所を決める**：上から見た図を作り、戦いの場所（±15m）に建物がかからない広場を選ぶ。候補を図で見せて、あなたに決めてもらう
4. **取り込み**：Godot は .glb をそのまま読める（プラグインはいらない）。`.glb.import` の設定で、当たり判定は作らない（このゲームは床の高さと正方形の範囲で判定しているため）
5. **古いマップと入れかえ**：`_build_world()` の緑の板をやめ、北千住を読む（**古い板は残さない**）
6. **合わせる**：`bounds`・`boss_position`・小さい敵の位置・カメラ・光の向き・空の色を、選んだ場所に合わせる。キャラの足が地面に合っているか（埋まる・浮く）を、写真とテストで確かめる
7. **軽くする**：数を見て、範囲・まとめ方・見える距離を調整。画質「低」の時は遠くを早めに消す
8. **テスト**：`tests/test_map_kitasenju.gd`＋今の全テスト。写真（上から・戦いのカメラ・縦と横）
9. **出典**を `assets/LICENSES.md` とクレジットに書く
10. **iPhone で確かめてもらう**（重さ・見え方）

## 5. データがない・足りない時の代わり
- **北千住が LOD1 だけ（屋根なし）の時**：LOD1 の箱の建物で作る（高さは本物）。ゲームの絵柄（色の面）に合うので、見た目はそれほど悪くならない。屋根の形がほしい所だけ、こちらで手で足す。
- **PLATEAU で足りない時**：
  - **OpenStreetMap**（だれでも編集できる世界の地図）：建物の形・道路がある。ライセンスは ODbL（**ゲームの中に「© OpenStreetMap contributors」と書く**のが条件。データそのものを配る時は、同じライセンスで配る）。高さは入っていない建物が多い。
  - **国土地理院の地図**（基盤地図情報・地理院タイル）：道路・建物の形・標高がある。使い方によって、出典の書き方や申請が変わるので、**使う前に利用規約を確かめる（未確認）**。
- **どれも使いにくい時**：本物の地図を見ながら、駅・高架・大きな建物・道の形だけを、こちらで手で作る（似せた形で、写真や看板は使わない）。
